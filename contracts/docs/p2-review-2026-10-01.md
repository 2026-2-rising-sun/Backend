## 검토한 의미 변경

| 계약 | 제공 코드와 대조한 경계 |
|---|---|
| Member | 공개 가입·로그인, JWT 본인 프로필 4개 operation. 추가 입력 필드 거부, 가입 201, 중복 409, 저장소 장애 503, ApiResponse 봉투, 실제 로그인 토큰 DTO |
| Commerce | 20개 operation. 거래는 JWT 회원 본인만, 관리 판매·재고는 ADMIN, 판매 조회는 Shopping/Live caller. 장바구니·멱등 재요청 200/신규 201, 빈 204, 성공 DTO와 오류 봉투 구분 |
| Shopping | 12개 operation. 상품·이미지는 공개, 관리는 ADMIN, 내부 상품은 Commerce/Live caller. 반복 ids, 상대 이미지 URL, Commerce 장애 503 유지 |
| Live | 13개 operation. 공개 방송 조회 유지, 방송 관리 ADMIN, HTTP 의존과 오류 응답 유지 |

각 서비스의 controller, 요청/응답 DTO, SecurityFilterChain 및 예외 처리와 대조했다.
USER와 ADMIN 모두 타인 주문·결제·장바구니에는 404이며, caller 자격증명과 사용자 JWT는 대체되지 않는다.
비회원 주문 비밀번호 제거와 관리 경로 인증 요구는 의도한 호환성 변경이다. 프론트 호환 완료를 주장하지 않는다.

검토 과정에서 Member의 unknown field 제한, 선택적인 직접 주문 금액의 null,
결제 시작 본문의 생략/빈 객체/null 및 Member 전체 저장소 오류 선언을 수정 요청하고 반영을 확인했다.
결제 null 요청과 실제 응답의 런타임 대조는 별도 HTTP 통합 harness에서 확인한다.

## 실행한 검증

root 통합 checkout에서 다음 명령을 독립 실행했다.

```sh
npm run check --prefix scripts/contracts
npm run smoke --prefix scripts/contracts
```

- Node 테스트 5개 성공, 실패·skip 0.
- OpenAPI 4개 lint 오류·경고 0.
- schema 75개, 참조 350개, 예시 100개 검증 성공.
- Prism에서 네 계약의 이름 있는 정상·오류·204 응답 32개를 요청해 지정 예시와 정확히 일치함을 확인.

이 기록은 계약 의미·형식·예시의 검토다. 실제 가입/로그인, 소유권, 재고, 멱등성 및 장애 시 DB 불변의
완료 증거는 별도의 동일 SHA HTTP 통합 결과와 PostgreSQL 테스트 보고서로 확인해야 한다.
Prism은 실제 JWT 검증이나 상태 있는 업무 처리를 증명하지 않는다.

refresh 회전·로그아웃·탈퇴·소셜과 Apidog 프로젝트 왕복 검증은 이 계약의 완료 범위가 아니다.
구조 변경 gate는 정확히 일치하는 독립 검토 기록을 요구하지만 자동 하위 호환성 증명이나 사람 승인 검증기는 아니다.
