판단과 실행의 기록

선택 이유·진행 상태·실제 작업 결과와 실패 경험을 남깁니다.

당시 조건을 보존하고 상태 변경·정정·후속 결정을 연결합니다.

MD — 설명과 근거. AI 에이전트가 읽고 참조하기 쉽게 구조화하며, 사람도 이해할 수 있는 문장·표·링크로 씁니다.

HTML — 시각적 이해. 구조·흐름·상태·차이를 그림과 비교 화면으로 설명하고, 필요한 상호작용을 제공합니다.

모듈 문서는 한곳에서, 원본은 명확하게

각 모듈의 docs/design-docs/services/모듈명/README.md에서 책임·소유 데이터와 API·DB·상태 문서를 연결합니다.

  • API 명세
    계약 YAML → api.html
    기존 계약에서 생성합니다. 명세 전체를 MD에 다시 복사하지 않습니다.
  • DB ERD
    마이그레이션·엔티티 → erd.md ↔ erd.html
    테이블·키·관계를 설명하고 물리 FK와 논리 참조를 구분합니다.
  • 상태·수명 주기
    구현·테스트 → states/주제.md ↔ 주제.html
    실제 전이 조건·실패·복구 경로를 대조합니다. 코드 조사와 실행 결과는 구분합니다.

모듈 문서와 생성 도구를 구현했습니다. 기준 소스·확인 범위·미확인 사항을 표시하고, 코드 조사와 실제 DB·HTTP·브로커 실행 결과를 구분합니다. 모듈별 문서 범위 보기

#330 하네스 변경 계획에서 구현 결과·검증 방법과 관련 판단·조사 자료를 확인할 수 있습니다.

선택·미연결 항목: guard.sh, post-edit.sh, MCP·Claude 설정은 아직 파일 생성과 훅 등록을 하지 않았습니다. 실제 사용할 기능을 구현·연결하고 실행을 확인한 뒤 상태를 갱신합니다.

기록과 기준을 연결합니다. 채택한 내용을 공유 문서에 반영하고, 선택 이유와 실제 검증 근거를 서로 연결합니다. MD의 핵심 내용이 바뀌면 관련 HTML도 함께 확인합니다.

내용이 생길 때 해당 문서를 추가합니다. 파일을 옮기거나 이름을 바꾸면 이 구조와 관련 링크를 함께 갱신합니다.
