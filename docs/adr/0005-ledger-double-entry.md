# ADR 0005: 원장은 상태 변경과 같은 트랜잭션에서 복식 분개한다

결정 상태: 제안
구현 상태: [원장 요구사항](../requirements/ledger.md)에서 추적
관련 자료: [이벤트 스토밍 원장](../exec-plans/active/337-payment-redesign/event-storming-v41.html#f9)

## 문제

결제·환불·정산 테이블의 상태 컬럼은 덮어쓰기라서 "언제 얼마가 어디로" 이력이 사라진다. 판매자 잔액 계산식이 화면마다 달라진다.

## 결정과 대안

- 돈이 움직이는 상태 변경(승인, 환불 성공, 정산 항목, 지급)마다 차변 합 = 대변 합인 분개를 추가만 한다.
- 분개는 같은 Payment DB에 상태 변경과 같은 트랜잭션으로 쓴다. 같은 사건은 UNIQUE(ref_type, ref_id)로 1번만 남긴다.
- 지급대행을 쓰므로 PG 입금과 PG 수수료는 기록하지 않는다.
- 대안: 상태 테이블 조합으로 계산하거나 이벤트로 비동기 기록. 이력이 없거나 분개 누락이 생길 수 있어 택하지 않았다.

## 영향

쓰기 트랜잭션이 조금 길어진다. 계산 버그는 원장 대사로 찾는다.
