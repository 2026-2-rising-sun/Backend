# ADR 0372: 상품 통합 등록의 DB 원자성과 파일 복구

상태: 채택·로컬 구현. 운영 배포 결과는 아니다.

## 문제

이미지 업로드·상품 등록·판매 등록이 분리돼 SKU 없는 상품이 남을 수 있다. DB 트랜잭션에 포함되지 않는 파일은 등록 롤백이나 프로세스 중단 후 남을 수 있다. 상품·SKU 이벤트가 다른 토픽에 도착하므로 동일 DB 커밋도 Catalog의 동시 반영을 보장하지 않는다.

## 결정

통합 등록은 Product와 SKU의 내부 포트를 동기 호출한다. 이미지 메타데이터·상품·모든 SKU·Outbox·최초 응답을 한 DB 트랜잭션으로 커밋하고 Product true·SKU ON_SALE을 최초 값으로 저장한다. 기존 분리 API의 준비 상태는 유지한다.

파일 저장 전에 판매자+멱등키의 복구 기록을 별도 커밋한다. 업무 트랜잭션은 그 행을 잠근 채 파일 I/O도 수행한다. 같은 키의 재시도와 정리 작업은 같은 잠금으로 직렬화하며, 정리 작업은 활성 요청을 SKIP LOCKED로 건너뛴다. 파일 키와 요청 지문을 보존하므로 중단 후 같은 파일을 재사용하거나 회수한다. 완료 응답은 최초 스냅샷으로 저장하며 자동 만료시키지 않는다.

파일 I/O를 잠금 밖으로 분리하고 lease·fencing을 도입하는 대안은 이번 범위에서 채택하지 않는다. 현재 로컬 저장소와 최대 이미지 크기에서 흐름을 단순하게 유지하는 대신 저장 중 DB 연결·행 잠금을 점유한다. 저장 지연에 대한 운영 측정 결과는 아직 없다.

Product 이벤트에 선택적 initialSkuCount를 추가한다. Catalog 기존 단일 판매 조회는 다중 SKU의 일부만 수신한 상태에서도 이를 단일 SKU로 축약하지 않고 503으로 거절한다. 대표 가격·합산 재고·고객 옵션 선택 정책은 이번에 정하지 않는다. 단일 SKU 상품은 기존 공개·구매 조건을 따른다.

## 영향과 적용 순서

Catalog V4·새 소비자/조회 코드를 먼저 전체 적용하고 Core V108·새 생산자를 전체 적용한 뒤 통합 API를 연다. 구형 소비자와 혼재한 동안의 통합 등록 노출을 허용하지 않는다.

정리 대상은 통합 등록 복구 기록이 소유하고 이미지 메타데이터가 없는 파일뿐이다. 기존 단독 업로드의 미참조 파일을 일괄 삭제하지 않는다. 완료 복구 기록의 보관·삭제 정책과 원격 저장소 도입은 별도 후속 결정이다.

구체적인 현재 동작과 검증은 [Product 설계](../design-docs/services/commercecore/product/overview.md#이미지상품sku-통합-등록-372)와 [작업 기록](../worklog/2026-11-19-product-registration.md)을 따른다.
