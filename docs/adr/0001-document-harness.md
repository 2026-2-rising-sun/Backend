# ADR 0001: 행동 기준·현재 지식·실행 기록을 연결한다

결정 상태: 채택
구현 상태: [요구사항](../requirements/document-harness.md)에서 추적
관련 작업: [#330](https://github.com/2026-2-rising-sun/Backend/issues/330)

## 문제와 대안

문서 수를 줄이는 데 집중하면 결정 이유·실패 경험·검증 범위를 다음 작업에 전달하기 어렵다. 모든 문서를 작업별 폴더에만 두면 현재 설계가 여러 과거 작업에 분산된다. 문서 종류별 폴더만 두면 복잡한 작업의 자료를 함께 찾기 어렵다.

## 결정

- 행동 기준은 AGENTS·가이드, 현재 지식은 명세·요구사항·설계, 기록은 ADR·계획·워크로그로 구분하고 서로 연결한다.
- 문서 종류별 폴더를 docs 바로 아래에 두고 복잡한 작업은 실행 계획 안에서 작업별로 묶는다. 공통 ADR과 일일 워크로그는 링크한다.
- MD는 사람이 읽을 수 있는 에이전트 참조 자료, HTML은 시각적 이해를 위한 자료로 쓴다. API는 기존 YAML에서 HTML을 생성한다.
- 중요한 결정에 ADR, 여러 단계의 작업에 계획, 실제 변경·조사·검증에 워크로그를 작성한다. 모든 작업에 세 파일을 요구하지 않는다.
- 훅·가드는 실제 필요와 호출 경로가 검증될 때 추가한다. 지침과 자동 검사를 구분한다.

## 영향

현재 설명과 과거 사실을 각각 갱신·보존할 수 있다. 코드 변경 시 관련 문서 검토 비용이 생기므로 원본 링크·생성 최신성·로컬 링크 검사를 연결한다. 의미의 일치와 실제 실행 여부는 사람과 에이전트의 문맥 검토가 필요하다.
