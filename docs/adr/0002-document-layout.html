ADR 0002: 흐름·서비스 설계·결정·실행 기록으로 문서를 모은다

결정 상태: 채택 선행 결정: ADR 0001 실행 기록: 2026-11-17

문제

서비스 설명과 모듈 설명이 서로 다른 경로에 있고, 현재 설계·작업 상태·결정 이유가 반복됐다. 화면 캡처와 수동 구조도가 원본과 함께 남아 갱신할 위치를 늘렸다. MD와 HTML의 짝 구성도 주제마다 달랐다.

결정과 대안

  • 서비스 간 흐름은 design-docs/flows/, 서비스·모듈별 ERD·API·업무 설명은 design-docs/services/에서 관리한다. CommerceCore는 Product·SKU·Cart·Order·Coupon으로 나눈다.
  • 흐름·설계·ADR·워크로그는 주제마다 MD·HTML 한 쌍을 둔다. MD는 설명·근거 원본, HTML은 같은 내용을 목차·관계도·표로 탐색하는 화면이다. API는 계약 YAML에서 두 파일을 생성한다.
  • ADR은 문제·대안·선택 이유를, 워크로그는 실제 변경·검증 결과를 소유한다. 현재 설계를 이곳에 다시 복사하지 않는다.
  • 진행 중인 계획은 worklog/plans/active/, 완료 계획은 completed/, 과거 하네스 구축 근거는 worklog/archive/에 보존한다. 이동을 업무 완료로 처리하지 않는다.
  • 별도 상태 문서는 관련 서비스·모듈 개요에 통합한다. 재현 목적이 없는 화면 확인 PNG와 수동 디렉터리 구조도는 정리한다.

기존 경로를 유지하고 지도만 추가하는 대안은 같은 주제의 원본을 계속 여러 곳에서 관리하게 한다. 모든 HTML을 없애는 대안은 사람이 관계·흐름·API를 탐색하려는 요구와 맞지 않아 선택하지 않았다.

영향

이동한 문서의 상대 링크와 코드·계약 참조, 검사기·생성기·CI 경로를 함께 갱신한다. 생성 파일 수는 MD·HTML 쌍 요구에 따라 늘어나지만 직접 편집하는 원본은 중복하지 않는다. HTML 최신성·쌍 구성 검사를 연결하고 화면 의미는 별도로 검토한다.

기존 Payment 목표 설계는 수작업 그림을 보존한다. MD를 함께 두고 원본 지문 변경을 검사하며, 해당 쌍의 의미 일치는 직접 대조한다. 가이드·템플릿은 문서 작성 도구이므로 별도 HTML을 강제하지 않는다.
