# Order 상태 설명 — 목표 전이 초안

[상태관리도.html](상태관리도.html) · [상세설계](설계.md) · [실행 계획](../../../exec-plans/active/331-order-module/README.md)

상태: 구현 진행 중. 생성/만료/환불 정책은 확정됐으며 아래 enum 이름과 환불 동시 접수 제한은 기술 제안이다. 현행 `PENDING_PAYMENT`/`PAYMENT_CONFIRMING` 상태를 이미 변경했다고 해석하지 않는다.

## 주문 전이

| 전이 | 조건 | 같은 DB 트랜잭션의 효과 |
|---|---|---|
| 생성 → PENDING | 주문서 생성, 모든 SKU 검증 성공 | 스냅샷 저장, available 감소/reserved 증가, 10분 기한 |
| PENDING → PAID | 해당 결제의 확정 성공, 기한 전, 식별자·금액 일치 | reserved 감소, 쿠폰 사용 확정, Cart 조건부 정리 |
| PENDING → FAILED | 10분 만료 또는 확정 결제 실패 | 예약 수량 해제, 해당 쿠폰 예약 해제, 필요한 종료 통지 의도 저장 |
| PENDING → CANCELLED | 사용자 취소. 결제 전달 요청 저장 전만 허용하는 안 | 예약 해제; 진행 중 즉시 취소 제한은 U3 사용자 확정 |
| PAID/PARTIALLY_REFUNDED → PARTIALLY_REFUNDED | 일부 항목/수량의 환불 성공 최초 적용 | 성공 수량만 available 증가, 쿠폰 사용 유지 |
| PAID/PARTIALLY_REFUNDED → REFUNDED | 전량 환불 성공 | 마지막 성공 수량 복구, 해당 주문 쿠폰 복원 |
| FAILED/CANCELLED → 동일 상태 | 지연 결제 성공/보상 환불 결과 | 금전 보상만 처리, 재고 재복구·주문 부활 없음 |

10분 만료는 신규 주문서 정책에서 결제 요청 전달 여부·UNKNOWN과 무관하게 유지한다. 기존 활성 구매의 정책 버전 0은 과거 상태/TTL을 보존한다. 결제 실행 미확정은 독립 Payment/연계 기록의 사실이며 Order 성공/실패 정책의 원본이 아니다. 현재 결과 이벤트는 SUCCESS/FAILED만 발행하므로 Order에 UNKNOWN 이벤트가 온다는 전제를 두지 않는다.

## 환불 건의 전이

| 전이 | 조건 | 효과 |
|---|---|---|
| 접수 → 처리 중 | 소유권·남은 수량·확정 금액 검사 | 환불 건/항목과 전달 요청 저장, 재고 변경 없음 |
| 처리 중 → 동일 상태 | 조회 지연·응답 유실·UNKNOWN | 수량을 새 환불에 다시 열지 않음 |
| 처리 중 → 성공 | 식별자·금액이 일치하는 확정 성공 | 환불 적용 여부와 SKU 복구 및 쿠폰 정책을 같이 커밋 |
| 처리 중 → 실패 | 확정 실패 | 성공 수량/재고 불변, 새 키로 재접수 가능 |
| 성공 → 성공 | 동일 성공 재전달 | 무변경 반환 |

주문 전체 상태만으로 부분 환불 중복을 판별할 수 없다. 서로 다른 환불 건과 한 건의 재전달을 구분하는 기존 환불 기록을 활용한다. 상충하는 확정 결과는 덮어쓰지 않고 대조 대상으로 둔다.

## 경합·실패 복구

Order 행을 잠근 뒤 상태·기한을 판단하고 SKU 변경과 같이 커밋한다. 성공/만료가 경합해도 선점은 한 번만 확정 또는 해제된다. 처리 시각 기준 판정과 잠금 순서는 통합 검토안이다. 주문당 미확정 환불 한 건을 제안하며, 채택 시 같은 Order 잠금으로 수량/금액 배분을 직렬화한다.

결과 적용 중 오류는 적용 표식까지 롤백한다. 외부 HTTP 호출은 DB 잠금 밖에서 하며 영속 전달을 재시도한다. 만료 통지가 결제 요청보다 먼저 도착하는 순서 역전, 늦은 성공의 보상 실패는 Payment 계약의 선행 검토 항목이다.

## 미결정·표시 상태

U2(한 장/항목 하나·누적 전량 복원·원래 유효기간)와 U3(대기 중 즉시 취소 제한)는 확정됐다. U1도 단가 우선/남은 실결제액 상한으로 확정돼 구현·검증 중이며 상세한 결정 근거는 [설계의 미결정 목록](설계.md#14-상세설계-검토-후-남길-결정)에 남아 있다. HTML은 해당 제안을 포함한 초안이며 논리 설계 전체 승인을 의미하지 않는다.

기존 FigJam 스타일 HTML의 데스크톱/모바일 표시와 SVG별 기하 검증을 마쳤다. 새 하네스의 현재 상태 MD/생성 HTML은 구현 변경 때 함께 갱신한다. 이번에 HTML이나 현재 구현 설명을 목표 상태로 덮어쓰지 않았다.
