# Order 상태와 결과 적용

[상태관리도.html](상태관리도.html) · [상세설계](설계.md) · [ERD](ERD.md) · [현재 Core 상태 설명](../../services/commercecore/states/order.md)

기준: Core V104·Payment V4. 새 API의 PENDING은 물리 PENDING_PAYMENT이며 policy_version=1이다. 기존 버전0의15분·PAYMENT_CONFIRMING 호환은 별도로 유지한다. 전체 검증 상태는 [실행 계획](../../../exec-plans/active/331-order-module/README.md)을 따른다.

| 출발 | 도착 | 조건·원자적 효과 |
|---|---|---|
| 없음 | PENDING | 주문서 서버 생성. 스냅샷 저장, SKU available−q/reserved+q, 최초 생성+10분 |
| PENDING | PENDING | 결제 원문 저장·진행/UNKNOWN. 기한은 연장하지 않으며 coupon/amount는 결제 원문 저장 시 고정 |
| PENDING | PAID | 잠금 후 DB시각이 기한 전이고 SUCCESS 최초 적용. SKU reserved−q, 쿠폰 USED, Cart ID/member/version 조건부 삭제 |
| PENDING | FAILED/EXPIRED | DB시각≥기한. SKU available+q/reserved−q·쿠폰 예약 해제·필요한 Payment 종료 의도 저장 |
| PENDING | FAILED/PAYMENT_FAILED | 기한 전 확정 실패. 예약 해제. UNKNOWN은 확정 실패가 아님 |
| PENDING | CANCELLED | 결제 요청 저장 전 취소만 가능. 한 번 예약 해제 |
| PAID/PARTIALLY_REFUNDED | PARTIALLY_REFUNDED | 일부 수량의 환불 성공 최초 적용. 해당 성공 수량만available+q, 쿠폰 USED 유지 |
| PAID/PARTIALLY_REFUNDED | REFUNDED | 주문 전체 항목 수량이 누적으로 환불 성공. 이번 성공 수량만 복구하고 해당 쿠폰 사용 건 한 번 복원 |
| FAILED/EXPIRED | FAILED/EXPIRED | 늦은 SUCCESS를 원결제 사실로 보존하고 전액 보상 의도 저장. SKU·Cart·쿠폰 효과를 재적용하지 않음 |

결제 결과 대기 중 즉시 취소 제한은 사용자 확정이다. 만료와 성공은 같은 root/회원 잠금 아래 DB시각으로 판정한다. PG 승인 시각이 기한 전이더라도 Core의 늦은 적용으로 주문을 부활시키지 않는다. 주문 실패와 Payment 실행 실패는 다른 사실이다.

## 환불 건

주문별 미확정 사용자 환불 한 건을 root 잠금으로 직렬화한다. PROCESSING/UNKNOWN은 성공 수량으로 세지 않는다. SUCCESS/FAILED는 저장된 실행 식별/원문/금액과 대조하며 중복은 무변경이다. SUCCESS 최초 적용은 환불 결과·항목/주문 상태·SKU 복구·필요한 쿠폰 복원을 같은 트랜잭션으로 처리한다. 반영 오류는 모두 롤백해 같은 결과로 재시도한다. 확정 실패는 복구 없이 기록하고 새 요청 키로 재접수할 수 있다.

환불액은 `min(스냅샷 단가×이번 수량, 해당 항목 실결제액−이전 성공 환불액)`이다. 4000×3/쿠폰2000은 순차4000/4000/2000, 처음2개면8000이다. 잔액0 수량도 환불 성공·재고·전량 완료를 처리하되 실제 PG0원 호출은 없다.

쿠폰 적용 항목 하나를 전량 환불해도 다른 항목이 남으면 복원하지 않는다. 여러 환불에 걸쳐 주문 전체 수량이 성공했을 때만 한 번 복원하고 원래 유효기간을 유지한다. 이후 재사용된 쿠폰은 과거 결과 중복으로 해제하지 않는다.

## 독립 Payment와 복구

종료 전달 의도는 만료와 같은 Core 트랜잭션에 저장한다. Payment는 원 paymentId/paymentRequestId 제어키로 생성·종료·호출 시작을 직렬화한다. 미호출은 승인 차단, 이미 호출 중/UNKNOWN은 재승인 없이 결과 조회, 늦은 SUCCESS는 원결제 전액 보상으로 수렴한다.

일반 환불 off에서도 검증된 종료 COMPENSATION만 전달·실행·복구한다. 종료 미도착503은 재시도하고 원문 변경409와 구분한다. 보상 적용에는 주문/재고/Cart/쿠폰 부수 효과가 없다.0원 늦은 성공에는 환불 원장을 새로 만들지 않는다.

실제 서비스·PostgreSQL/HTTP·브라우저 검사는 [워크로그](../../../worklog/2026-11-13.md)에 기록한다. 외부 PG·브로커·AWS·CI 증거와 확대 해석하지 않는다.
