옵션이 다른 상품은 별도 SKU 항목으로 관리합니다. 기존에 담긴 항목에 판매정보가 없더라도 지우지 않고 남겨 두며, 주문 선택에서는 이용 불가로 처리합니다.

구현 중 · V103 검증 대기

기준: cc91c09b 위의 Cart 구현 변경 · MD 원본 · 상세 설계 · 구현 계획 · 현행 Core 전체 ERD

현재 데이터와 목표 모델을 구분합니다. sku_id는 Cart 엔티티와 V103 확장에 반영 중입니다. 실제 PostgreSQL 이행 검증은 아직 완료하지 않았습니다. nullable SKU는 기존 항목의 보존을 위한 것이며 가격·재고 원본을 Cart에 만드는 의미가 아닙니다.

상품·SKU·회원과 Cart의 관계

점선은 논리 참조입니다. 아래 관계에 물리 FK를 추가하지 않습니다. 좁은 화면에서는 도표 안을 가로로 이동할 수 있습니다.

논리 참조 / 물리 FK 없음SKU·Member 하나에 Cart 항목 여러 개Order는 Cart 삭제 뒤에도 출처 값을 유지

Cart가 저장하는 8개 필드

필드타입·제약의미
idBIGINT IDENTITY PK기존 항목 ID 보존
member_idVARCHAR(36), NOT NULL인증된 회원 UUID 문자열
product_idBIGINT, NOT NULL, 양수기존 상품 참조와 상품별 묶음
sku_idBIGINT, NULL 또는 양수SKU 구매 단위. 기존 매핑 불가 행만 NULL로 보존
quantityINTEGER, NOT NULL, 양수해당 SKU의 절대 수량
versionBIGINT, NOT NULL, 기본 0수량 변경과 원본 구매 출처 구분
created_atTIMESTAMP WITH TIME ZONE, NOT NULL생성 시각
updated_atTIMESTAMP WITH TIME ZONE, NOT NULL수정 시각

UNIQUE(member_id, sku_id)를 사용합니다. SKU가 없는 기존 행은 sku_id IS NULL 조건의 회원+상품 부분 유일 인덱스로 중복을 막습니다.

가격·재고·주문 상태·선택 체크·만료 시각은 Cart 저장 원본에 넣지 않습니다. 독립 Cart 업무 상태도도 만들지 않습니다.

V103은 기존 데이터를 넓혀 이행합니다

  1. nullable sku_id를 추가합니다.
  2. sales_info.product_id → sales_info.id → sku.id로 기존 기본 SKU만 연결합니다. 다중 SKU 중 임의 선택하지 않습니다.
  3. 회원+SKU 유일성과 미매핑 레거시의 부분 유일 인덱스를 적용합니다.
  4. ID·수량·버전·감사 시각과 Order/환불 출처를 보존합니다. 항목을 지우거나 임의 SKU를 만들지 않습니다.

선행 순서: V101 Product → V102 SKU → V103 Cart → V104 Order. legacy Sales 쓰기 전환 전 중간 상태는 독립 배포 가능한 완료 상태가 아닙니다.

결제 중 수량이 바뀌면 어떻게 정리하나요?

구매 당시의 Cart ID·회원·version이 같은 행만 결제 성공 후 삭제합니다. 수정되거나 다시 담긴 행과 선택하지 않은 항목은 남깁니다. 실패·취소·만료에는 성공 정리를 실행하지 않습니다. SQL 오류는 주문 상태·재고 변경과 함께 롤백합니다.

현재 검증: H2 JPA 선택·성공 정리 실행. 실제 PostgreSQL V103 이행·부분 인덱스·잠금 경합과 선행 모듈 통합 검증은 대기 중입니다. 동일 모델의 MD 원본과 실행 기록을 함께 확인하세요.
