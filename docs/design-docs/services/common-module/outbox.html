시각 자료

책임과 조건

업무 변경과 Outbox 삽입은 소유 서비스의 같은 DB 트랜잭션에 참여한다. 공통 모듈은 독립 DB를 소유하지 않는다. 기본 relay와 선택적인 DB claim 모드를 구분하며 스키마·설정이 준비된 서비스에서만 claim을 사용한다.

출발 도착 조건·부수 효과
업무 트랜잭션 미발행 행 EventOutbox로 메시지 원문과 eventId를 같은 트랜잭션에 저장한다. 롤백되면 함께 취소된다.

CDC와 relay의 배타적 전달

shoppinglive.outbox.relay.excluded-topics의 기본값은 빈 목록이라 다른 서비스는 기존 relay 동작을 유지한다. Core만 commerce.catalog.snapshots.v1을 제외한다. 일반 JPA 조회와 DB lease/claim 조회가 모두 같은 제외 목록을 적용하며, fast path도 이 조회를 사용한다. CDC 중단을 감지해 relay로 보내는 fallback은 없다.

Catalog Outbox 행도 기존 event_id/event_type/topic/message_key/payload TEXT/created_at을 그대로 사용한다. I의 connector는 public.event_outbox의 해당 토픽 create/read만 먼저 필터한 뒤 전체 봉투 TEXT를 원문 value로 보낸다. 관리 UPDATE/DELETE는 비즈니스 이벤트가 아니다. CDC는 published_at/attempts를 relay 완료로 갱신하지 않는다. NULL published_at을 실패나 TTL 정리 가능으로 단정하지 않으며 이번 변경은 CDC 행 삭제를 추가하지 않는다. 보관·slot·offset checkpoint 정리는 별도 운영 설계가 필요하다.
