Live Service API

계약 YAML · OpenAPI 3.1.0 · 계약 2.0.0

계약에 선언된 API입니다. 실제 응답·인증·외부 서비스 실행 결과는 워크로그에서 확인합니다.

방송·프로모션·채팅·좋아요 API. 서비스가 JWT를 직접 검증한다. JSON 성공·오류 응답은 ApiResponse 봉투이며 DELETE 성공은 204 무본문이다. SSE data는 이벤트별 JSON이다. 공개 방송 조회·입장은 비회원에게 허용한다. 방송·프로모션·상품 연결 관리에는 SELLER 역할이 필요하다. 방송별 판매자 소유권은 구분하지 않는다. 공개 응답에는 채널 ARN·등록 키·송출 자격증명을 포함하지 않는다. Bearer가 있으면 Member 세션을 확인하며 유효하지 않은 토큰은 401, 세션 확인 장애는 SERVICE_UNAVAILABLE 503이다. 공개 경로의 무토큰 요청은 Member 세션을 확인하지 않는다.

로그인 없이 연결한다. LIVE 방송에만 연결할 수 있고 그 외 상태는 409 다. 연결 전 오류는 Accept 헤더와 무관하게 JSON 오류 봉투이고, 연결 후에는 오류 본문 없이 연결이 닫힌다.

이벤트(event: 이름과 data: JSON. data 는 ApiResponse 봉투가 아니다):

event data 시점
stream.ready StreamReadyEvent 연결 직후 한 번
chat.created ChatMessage (id: 는 messageId) 채팅 저장 후. 방송별 초당 예산을 넘은 일반 채팅은 생략

promotion.opened PromotionStreamEvent 프로모션이 OPEN으로 전이한 뒤
promotion.closed PromotionStreamEvent 열렸던 프로모션의 수동 종료·시간 만료 뒤
broadcast.ended BroadcastEndedEvent 방송 종료 시. 이후 서버가 연결을 닫는다

클라이언트 규칙: - stream.ready를 받은 뒤 최근 채팅·좋아요 합계·열린 프로모션을 GET으로 조회한다. 프로모션 조회 경로는 /v1/broadcasts/{broadcastId}/promotions이며 채팅은 messageId로 중복을 제거한다. - broadcast.ended를 받으면 열린 프로모션 표시를 종료하고 재연결하지 않는다. 마지막 좋아요 합계를 GET으로 조회한다. 받지 못하고 끊겼다면 재연결이 409 일 때 방송 상태와 합계를 조회한다. - 전달은 보장하지 않는다. 재연결 요청의 Last-Event-ID(마지막으로 받은 messageId)가 최근 2분 안의 채팅이면 stream.ready 뒤에 그 채팅 시각 5초 전부터의 채팅을 chat.created로 다시 보낸다(최대 256건). 겹치는 채팅은 messageId로 거른다. 채팅 외 이벤트는 다시 보내지 않는다. 재연결 후 채팅은 최근 50건, 좋아요와 프로모션은 현재 상태 조회로도 복구한다. - 약 15초마다 comment 줄(:heartbeat)이 온다. 수신이 느려 대기량을 넘으면 서버가 연결을 닫는다. - 서버는 연결을 최대 30분 유지한다. 닫히면 다시 연결한다. 재연결이 409 이면 방송 상태를 조회한다.
