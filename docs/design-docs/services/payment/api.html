Payment Service 내부 API

계약 YAML · OpenAPI 3.1.0 · 계약 2.0.0

계약에 선언된 API입니다. 실제 응답·인증·외부 서비스 실행 결과는 워크로그에서 확인합니다.

브라우저 공개 경로가 없는 결제 실행 서비스. Commerce(commercecore)만 X-Service-Token으로 부른다. 결제 1건의 업무 키는 Commerce가 준 orderRef이고, 토스 결제창 orderId는 {orderRef}-{결제창 회차}인 pgOrderId다. 이 서비스의 API는 토스를 부르지 않는다. 시간 판단(만료)은 Payment DB 시각으로 한다. 승인 API(/v1/internal/payments/{orderRef}/approval)는 경로만 허용돼 있고 #338에서 정의한다.

POST /v1/internal/payments

결제 생성(같은 orderRef는 멱등)

새 orderRef면 CREATED 결제와 판매자별 금액을 저장하고 201, 첫 pgOrderId는 {orderRef}-1이다. 같은 orderRef가 이미 있으면 위에서부터 처음 맞는 규칙으로 응답한다. (1) amount 또는 buyerId가 다르면 409 AMOUNT_CONFLICT. (2) CREATED이고 만료 전이거나 APPROVING·UNKNOWN·APPROVED면 200으로 현재 값을 준다. (3) 만료된 CREATED·CANCELED·PARTIALLY_REFUNDED·REFUNDED면 409 PAYMENT_CLOSED. 재요청의 expiresAt·sellerAmounts는 비교하지 않고 처음 값을 유지한다. 동시 요청도 결제 1건이다. 검증 순서는 Bean Validation(INVALID_REQUEST) → orderRef 형식 → 판매자 금액 합 → 요청 안 판매자 주문 번호 중복 → (같은 orderRef가 없을 때만) expiresAt이다. 같은 orderRef가 있으면 요청의 expiresAt이 지났어도 검사하지 않고 위 규칙으로 응답한다.
