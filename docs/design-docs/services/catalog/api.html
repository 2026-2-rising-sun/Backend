Catalog 공개 상품 조회 API

계약 YAML · OpenAPI 3.1.0 · 계약 2.1.0

계약에 선언된 API입니다. 실제 응답·인증·외부 서비스 실행 결과는 워크로그에서 확인합니다.

Catalog는 Core 상품 원본 snapshot과 기존 판매·쿠폰 사본으로 공개 상품 목록·상세·구매 사전확인·쿠폰 조회를 제공한다. 상품 쓰기·판매자 관리·이미지 파일과 내부 상품 조회는 CommerceCore가 소유한다. 사본 반영은 비동기이며 가격·재고의 최종 검증은 Core 주문 생성 시 수행한다. 기존 /v1 응답 DTO와 사본 조회 기본값을 유지한다.

공개 상품 목록

검색 인덱스(Elasticsearch)에서 조건에 맞는 상품을 정렬된 순서로 찾고, 가격, 재고, 판매 상태는 응답 때 product_sales 이벤트 사본에서 붙인다. Commerce가 응답하지 않아도 200을 반환한다. 검색 인덱스는 사본 변경 뒤 몇 초 늦게 반영되며, 그 사이 삭제되거나 공개 대상이 아니게 된 상품은 응답에서 뺀다. 상세·주문 가격 확정은 기존 경로를 유지한다. q는 상품명을 한국어 형태소 단위로 검색한다. 조사나 띄어쓰기가 달라도 찾으며(무선이어폰, 무선 이어폰) 검색어의 단어가 모두 들어간 상품을 반환한다. 자주 쓰는 동의어와 영어 표기도 찾는다(셔츠, shirts). 대소문자를 구분하지 않고 특수문자는 무시한다. 가격 동률은 ID로 정렬한다. cursor는 같은 q/status/category/sort 조건에서만 재사용하며 조건 변경 시 생략한다. 조회 도중 가격·상태 변경 시 실시간 목록 특성상 페이지 간 위치가 바뀔 수 있다. category는 해당 분류 상품만 반환하며 생략하면 미분류(null)를 포함한 전체다. 미분류만 고르는 값은 없다. q/status/category/sort를 모두 생략하면 sort=LATEST와 같은 결과를 반환한다. 이전 형식의 cursor는 400 INVALID_REQUEST다. SKU가 여러 개인 상품은 한 줄로 반환한다. 판매 중 SKU가 하나라도 있으면 ON_SALE이고 price는 판매 중 SKU 최저가, available은 판매 중 SKU 재고의 합이다. 모두 품절이면 SOLD_OUT이고 품절 SKU의 최저가와 재고 합이다. 가격 정렬과 가격 기준도 이 대표 가격이다. 비공개 SKU는 계산에서 뺀다. 검색 인덱스에 연결할 수 없으면 사본으로 대신 검색하지 않고 503 SERVICE_UNAVAILABLE이다.

상품에 적용 가능한 쿠폰

Commerce 쿠폰 이벤트로 채운 replica를 읽는다. 요청마다 Commerce를 호출하지 않는다. startsAt <= 지금 < endsAt인 쿠폰만 endsAt 오름차순으로 준다. 소진된 쿠폰도 soldOut=true로 준다. 회원별 보유·사용 여부는 주지 않는다. 받기와 최종 적용 판정은 Commerce가 한다. 쿠폰이 없거나 모르는 상품이면 빈 목록이다. 쿠폰 적용 예상가는 클라이언트가 판매가 - fixedDiscount(0 미만은 0)로 계산한다. 표시정보는 Commerce보다 늦을 수 있다. 보통 이벤트 전달 시간만큼 늦고, 이벤트를 놓치면 다음 주기 동기화(기본 10분)에 맞춰진다. 이 API가 실패해도 상품 상세 API에는 영향이 없다. 화면은 쿠폰 영역만 숨기고 상품은 그대로 보여 준다.
