CommerceCore DB ERD

전체 관계도 1

화살표 번호는 아래 관계·처리 조건표의 행 순서입니다. 배치는 실행 순서가 아닙니다.

기준: Product #333 729d2d5f·SKU #334 1a09aacd·Cart V103·Order 독립 V104를 통합했다. 새 판매와 구/신규 주문 거래는 SKU 원본을 사용하며 sales_info/sales_stock은 이행 입력과 과거 참조로 보존한다. Cart의 선택·조건부 성공 정리 포트도 같은 주문 트랜잭션에 연결한다. 독립 결함 보완과 범위 정정 검증 중이며 전체설계는 미충족·머지불가다. 실제 DB·HTTP·Kafka·PG 제공자 결과는 워크로그와 구분한다. SKU 상세 · Order 상세.

시각 자료 · Cart 모듈 상세 ERD · Order 전체 관계도

전체 CREATE/ALTER 순서를 대조한 테이블·핵심 키·관계 요약이다. 전체 열 타입·인덱스·CHECK와 데이터 이관 SQL은 아래 원본을 따른다. 운영 DB에 적용된 실제 스키마를 조회한 결과는 아니다.

제약과 이관

V101은 기존 Product 전체 스위치를 true로 보존하고 신규 기본값만 false로 바꾼다. deleted_at이 있으면 전체 false CHECK를 유지하고 상품·이미지·하위 판매 행을 물리 삭제하지 않는다. Product 상세 ERD/상태에서 통합 목표와 현재 구현을 구분한다.

V3에서 비회원 lookup_password_hash를 제거하고 member_id를 필수화했다. V7 금액은 total_amount와 할인·실결제액을 구분한다. V11은 REFUNDED를 허용한다. V10·V12~V14 등 이관용 파일의 이름만 보고 현재 Core가 PG 테이블을 소유한다고 추정하지 않는다. V21 영속 전달과 Payment 원본을 구분한다. 진행 중 묶음의 회원별 부분 유일 인덱스가 있다.

Order V104 상세

논리 Order=payment_group/OrderItem=orders 매핑과 수량 환불·종료 기록 관계는 모듈 ERD에 있다. 전체 관계도는 그 모듈 HTML을 사용한다. 이 페이지의 생성 HTML은 테이블/관계 요약이며 통합 ER 그림을 대체하지 않는다. 기존 PK·번호·당시 금액·Cart 출처·활성TTL을 유지한다.

신규 order_payment_closure/COMPENSATION 목적·참조열과Payment V4는현재PR에서제외했다. 내부policy1은도메인검증만하며공개legacy는policy0/신규기본600초이다. 보존V104적용환경을변경하거나진행중policy1/2를0으로변환하지않는다.

V105는 별도 처리기한 컬럼과 늦은 승인 환불 필요 기록을 추가한다. 기존 생성기한·상태·정책0/1/2 확인중 데이터의 null 처리기한은 보존한다. Payment DB/제어행/종료API는 수정하지 않는다. V106의 새 계약 중계는 환불 요청 outbox와 결과 소비를 제공한다. 실제 Payment 환불 소비·결과 생산 검증은 미완이다.

통합 등록의 스키마 추가 (#372)

V108: product.initial_sku_count, sku.option_label, product_registration 복구 기록을 추가한다. 이미지·상품·모든 초기 SKU·Outbox·등록 결과의 업무 커밋과 파일 저장 전 복구 기록 커밋을 구분한다. 상세는 Product ERD와 SKU ERD를 따른다.
