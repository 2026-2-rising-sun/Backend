# 하네스 변경 계획의 판단 기준

상태: 채택 · 구현과 로컬 검증 완료 · 팀원별 적용은 미확인

[실행 계획](README.md) · [현황 조사](research.md)

## 하네스의 역할

하네스는 AI 에이전트가 요청 범위를 지키고 팀의 공통 기준으로 작업하도록 하는 지침과 실행 절차다. 필요한 프로젝트 지식과 실제 판단·실행 기록을 연결해 다음 작업에서 근거를 찾아갈 수 있게 한다.

## 문서 종류별 배치와 작업별 묶음

참고 이미지의 `product-specs`, `requirements`, `adr`, `design-docs`, `exec-plans`, `worklog`를 `docs/` 바로 아래에 둔다. 여러 작업에 지속적으로 적용되는 결정은 공통 ADR, 일일 결과는 날짜별 워크로그를 원본으로 둔다.

복잡한 작업의 실행 계획은 작업 폴더의 `README.md`로 관리한다. 그 작업에서만 쓰는 선택 이유·조사·실험 자료는 같은 폴더에 둔다. 하나의 작업을 이어받을 때 진입점을 통해 필요한 자료를 읽을 수 있게 하기 위한 선택이다. 공통 ADR과 워크로그는 내용을 중복 갱신하지 않도록 원본을 링크한다.

완료 후에는 작업 폴더를 `completed/`로 옮기고 연결된 링크를 갱신한다. 경로 이동에 따른 링크 점검은 이 방식의 관리 비용으로 받아들인다.

## 기록 작성 조건

중요한 결정에는 ADR, 여러 단계·의존성·인계가 있는 작업에는 실행 계획을 작성한다. 실제 변경·의미 있는 조사·검증 결과는 일일 워크로그의 작업 항목에 요약한다. 모든 작업에서 세 종류의 문서를 새로 만들지는 않는다.

이번 작업은 기존 하네스 이관, 문서 정책, 검사기와 CI 변경이 연결되므로 실행 계획과 판단·현황 자료가 필요하다. 모듈별 문서 범위·원본·진행 상태를 비교하기 위해 [tables.md](tables.md)를 추가했다. `prompts.md`는 재현할 입력을 별도로 보존할 필요가 있을 때 추가한다.

## MD와 HTML

MD에는 AI 에이전트가 읽고 참조할 핵심 설명·규칙·근거를 남긴다. 사람도 이해할 수 있는 문장·표·링크로 작성한다. HTML은 구조·흐름·상태·차이를 시각적으로 설명할 때 추가하고 원본과 연결한다. 모든 문서를 두 형식으로 만들지는 않는다.

## 모듈별 API·ERD·상태 문서

서비스별 설명 파일을 `docs/design-docs/services/<모듈명>/` 폴더로 확장한다. 모듈의 API·ERD·상태 문서를 한곳에서 읽을 수 있게 하고, 여러 서비스를 관통하는 흐름은 상위 설계 문서로 연결한다.

API 명세의 원본은 기존 OpenAPI YAML로 유지한다. API HTML은 계약과 공통 참조에서 생성해 명세의 수동 중복을 줄인다. ERD는 마이그레이션과 엔티티, 상태도는 실제 전이 코드·조건·테스트를 대조한 MD를 설명 기준으로 삼는다. 각 자료에 원본과 확인 범위를 표시한다.

CommerceCore에서 API·ERD·상태 문서 한 세트를 먼저 검증한 뒤 Payment·Catalog, Member·Live·Notification으로 확장한다. 현재 상태가 복잡한 대표 모듈에서 원본 대조와 화면 탐색 방법을 확인해 나머지 문서에 적용하기 위한 순서다. 공통 모듈은 독립 서비스가 아닌 공유 구현으로 설명한다.

## 검증 의미와 실제 연결 범위

기존 실패·스킵·0건·외부 환경 미실행·검사 중 변경 처리는 유지한다. 문서 완료 근거는 문서의 성격에 맞는 검사와 실행 결과를 표현할 수 있어야 한다. 자동 검사는 링크·상태·참조의 구조를 점검하고, 결정 이유나 검증 내용의 적절성은 문맥으로 검토한다.

사용할 기능이 정해지지 않은 가드·편집 후 훅·MCP 설정은 현재 연결된 것으로 표시하지 않는다. 팀의 실제 적용과 에이전트 실행 확인은 저장소의 문서 작성·정적 검사와 구분한다.

## 공통 ADR과 연결

문서의 배치·기록 작성 조건·검증 경계는 [ADR 0001](../../../adr/0001-document-harness.md)에 정리했다. 이 작업 문서는 작업에 필요한 판단과 구현 선택을 남긴다. 실제 실행 결과는 [워크로그](../../../worklog/2026-11-13.md)를 참조한다.

## 구현한 생성 방식

공통 결정 원본은 [ADR 0001](../../../adr/0001-document-harness.md)이다. API는 기존 고정 PyYAML 환경의 저장소 내부 렌더러 버전 1로 생성한다. 외부 뷰어 자산·CDN·Node 실행 의존성을 추가하지 않고 모든 선언과 로컬 참조를 표시한다. ERD·상태·상위 흐름 HTML은 MD의 관계·전이 표에서 생성해 이중 편집을 피한다. 이는 스키마 의미 검증기나 전체 Markdown 변환기가 아니며 지원 범위와 검토 방법은 도구 안내에 명시했다.
