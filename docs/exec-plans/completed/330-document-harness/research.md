## 문서 검사 기준선

계획 문서와 일일 기록을 추가하기 전에 실행했다.

```bash
.venv-api/bin/python scripts/check_docs.py
```

- 종료 코드: `1`
- 검사 대상: 문서 18개
- 오류: 19개, 모두 `AGENTS.md`의 로컬 링크 없음
- 대표 경로: `harness/README.md`, `harness/workflow/README.md`, `harness/quality/code.md`

이 결과는 현재 문서 검사기의 출력이다. 검사기 자체의 회귀 테스트 통과나 모든 Markdown 문법 지원을 증명하지 않는다. 문서 수는 이후 계획·기록 추가에 따라 달라지므로 최종 검증 때 다시 기록한다.

## 이번 조사에서 실행하지 않은 항목

- 문서 검사기·실행기·변경 선택기의 전체 회귀 테스트
- Java 빌드·서비스 테스트·실제 PostgreSQL·Kafka 검증
- 원격 CI 및 다른 팀원의 에이전트 작업
- 가드·편집 후 훅·MCP 연결

현재 변경의 목적은 계획 수립이며 위 구현·실행 결과를 완료한 것으로 취급하지 않는다.

## 모듈 문서 범위 추가 조사

사용자가 모듈별 API 명세·DB ERD·상태 전이도의 HTML 문서화까지 계획에 포함하도록 요청했다. 이전 단계에서 후속 범위로 두었던 서비스별 문서를 전체 변경 계획의 단계별 산출물로 추가했다.

6개 서비스의 API YAML과 마이그레이션 경로, 상태 관련 파일 이름을 확인했다. Payment는 `db/payment-migration/`을 사용한다. Catalog의 판매 상태 enum 설명과 CommerceCore의 주문 상태 enum을 일부 읽었으나, 실제 허용 전이 전체는 아직 확인하지 않았다. 상태 변경 서비스·영속 필드·테스트를 함께 읽어야 한다.

조사한 경로와 앞으로 작성할 자료는 [모듈별 문서 범위](tables.md)에 정리했다. 이 조사는 API 렌더링, DB 스키마 적용 결과, 실제 상태 전이 실행을 확인한 결과가 아니다.
