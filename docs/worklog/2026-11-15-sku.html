변경과 선택 근거

  • Catalog 목록이 product_sales 직접 JOIN으로 상세의 복수 SKU503 계약을 우회했다. 검색·카테고리·공개 상태에 맞는 상품의 전체 SKU 수를 커서·LIMIT 전에 검사하고 복수면503을 반환한다. PRIVATE 등 다른 상태의 SKU도 포함한다. 조건 밖/삭제 상품은 막지 않는다. REPEATABLE_READ로 검사와 페이지가 같은 사본 snapshot을 사용한다. MIN/DISTINCT 대표가격·임의 SKU를 선택하지 않는다.
  • 판매자 재고증감이 available만 INT_MAX로 채워 예약 해제를 막던 조건을 available+reserved 한도까지 검사하도록 수정했다. reserve/release는 합계를 유지하고 consume은 줄인다. restock도 같은 보충 조건을 사용하므로 예약 해제 공간을 보존한다. BIGINT 계산·INTEGER 저장의 기술 범위이며 구매당 업무 한도가 아니다.
  • Catalog sales_id PK·구매가능조건, Product Outbox 물리 message_key, 모듈 체크포인트와 후행 통합 기준을 교정한다. 과거 워크로그 수치/검증 결과는 덮어쓰지 않는다. 현행 문서의 미답변 기술 동작을 사용자 확정과 구분한다.

기존 선점 주문은 결제를 허용하고 새 주문만 막는 사용자 답변을 유지한다. 재고0 판매시작 성공·중지상품 공개 유지·Cart 담기 판매조건은 답변 대기이며 이번 작업에서 바꾸지 않는다. 공개 다중 SKU/대표가/옵션은 보류다.
