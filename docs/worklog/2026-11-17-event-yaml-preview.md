# 2026-11-17 이벤트 YAML 별칭 PR 통합 (#313)

## 목적과 현재 상태

사용자가 PR #361·#314의 내용을 확인하고 충돌을 해결한 뒤 병합하도록 요청했다. [#361](https://github.com/2026-2-rising-sun/Backend/pull/361)의 문서 구조 통합을 먼저 검증하고 dev에 병합했다(merge e79f2144). [#314](https://github.com/2026-2-rising-sun/Backend/pull/314)는 IntelliJ AsyncAPI 미리보기 호환을 위해 YAML 앵커·별칭을 명시적 정의로 펼치는 작업이다.

#314 작성 이후 [#329](https://github.com/2026-2-rising-sun/Backend/pull/329)의 e5a1b66b가 별칭 제거와 서비스 명칭 호환을 이미 반영했다. 최신 dev의 이벤트 YAML 8개에는 앵커·별칭이 없다. 예전 #314의 스키마로 덮으면 새 생산자 source와 스키마 참조·예시가 역행할 수 있으므로, 충돌한 쿠폰·결제 묶음·방송 계약은 최신 dev 원문을 보존했다. 이번 최종 diff는 계약 변경이 아니라 확인·충돌 해결 기록이다.

원래 작업 폴더의 미커밋 문서·그림·계획은 보존하고 `/tmp/backend-pr361-314-merge-20261117`의 독립 Git 체크아웃에서만 작업했다. 새 Orca 에이전트나 워크스페이스는 실행하지 않았다.

## 검증

- #314의 원래 기준과 원래 head ff20da02의 계약 3개를 파싱한 결과가 동일함을 확인했다. 원래 변경은 별칭 확장이며 의미 변경이 아니다.
- 충돌 해결 뒤 이벤트 YAML 8개 모두 최신 dev e79f2144와 원문·파싱 결과가 동일하고 YAML scanner의 AnchorToken·AliasToken이 각각 0개임을 확인했다. 파일별 SHA-256과 결과는 `/tmp/pr314-schema-preservation.json`에 보존했다.
- 현재 이벤트 계약 8개·예시 23개 검사와 API 경로 64개 정적 검사가 통과했다. 실제 이벤트 전달 검사가 아니다.
- 기존 #314 본문에 있던 Java 환경 부재로 인한 전체 빌드 실패와 직렬화 표본 미실행은 당시 기록이다. 이번에는 업무 코드·API·이벤트 원문을 바꾸지 않아 업무 빌드를 형식적으로 재실행하지 않는다. IntelliJ 플러그인의 실제 미리보기와 브로커 전달도 이번에는 재현하지 않았다.

## PR 설명과 전달

PR 제목·본문은 현재 변경에 맞춰 최신 계약 보존과 별칭 제거 상태 확인으로 갱신한다. 로컬 문서·생성 결과 검사와 최종 head의 원격 CI, 미해결 리뷰·병합 상태를 따로 확인한다. 실제 dev 병합 완료는 GitHub PR의 merge 기록을 기준으로 한다.
