# #372 이미지·상품·SKU 통합 등록

상태: 로컬 구현·검증 완료. 기준은 최신 dev `389e3ae0`이며 프론트 구현·커밋·푸시·PR은 범위 밖이다. 프론트 후속은 [Frontend #86](https://github.com/2026-2-rising-sun/Frontend/issues/86)이다.

## 목표와 범위

대표 이미지와 상품정보·1~100개 초기 SKU를 한 요청으로 받아 즉시 판매 상태로 생성한다. DB 원자성·재전송·파일 실패 복구·Catalog 부분 수신 보호를 포함한다. 기존 분리 API, 상품 수정, 주문 검증을 보존한다. 옵션은 표시명 범위로 한정하고 다중 SKU 고객 조회 정책을 임의 확장하지 않는다.

## 수용 기준

- [x] 판매자 인증·multipart·전체 입력 검증과 최초 판매 상태
- [x] 실제 PostgreSQL의 전체 저장·SKU/Outbox 실패 롤백·동시 재전송
- [x] 실제 로컬 파일 저장·실패 정리·중단 복구·참조 이미지 보호
- [x] Catalog 역순·부분 수신과 기존 단일 SKU 회귀
- [x] API·이벤트 계약·설계·ERD 생성과 문서 검사

## 실행 기록

[2026-11-19 작업 기록](../../../2026-11-19-product-registration.md)에 검증 명령과 환경·제한을 남긴다.

## 결과와 후속 범위

통합 등록 API, 복구 기록·이미지 정리, 최초 판매 상태, Catalog 부분 수신 보호를 구현했다. 실제 PostgreSQL·로컬 저장소·EmbeddedKafka 릴레이와 기존 외부 Kafka 회귀를 검증했다. 프론트 구현은 #86에서 진행한다. 고객 다중 SKU 선택·대표 가격/재고 정책, S3 등 원격 저장소, 운영 배포·저장소 다중 인스턴스 구성은 이번 완료 범위가 아니다. 기존 Catalog 단일 판매 API는 다중 SKU를 503으로 거절한다.
