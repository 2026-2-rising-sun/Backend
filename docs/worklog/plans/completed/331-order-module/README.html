#331 Order 구현과 통합 검증

역사 기록: e08b8aea 보존 구현의 당시 범위/실행이다. 2026-11-15 Payment 담당경계 정정으로 현재 PR의 신규 금전·종료/보상·legacy600초 확대는 제외했다. 현재 보완 계획의 미충족 원래 수용 기준을 따르며 전체설계완료·머지가능으로 읽지 않는다. 상태: 기존 범위 구현·검증 완료. 코드 기준 840825635f370960679621a7aa9a8237fe27bffb, Draft PR #343(base Cart). 사용자는 지금 기존 작업을 마무리하고 #345 동시 환불·#346 결제 준비/실행 기한 분리는 나중에 전용 작업 공간에서 진행하도록 요청했다. 두 후속은 사용자 요청으로 보류하며 이 계획의 완료를 정책 전체 승인·운영 검증·후속 구현 완료로 확대하지 않는다.

이슈 #331 · ADR 0331 · 상세설계 · ERD · 상태 · 워크로그 · 실제 검증 보고

범위와 완료 조건

  • 주문서 생성 시 UUID 주문번호·SKU 항목·서버 가격 스냅샷·선점을 같은 DB 트랜잭션으로 저장한다.
  • 신규 주문의 원래 10분 기한, 결제/만료 경합, 늦은 성공 보상, 수량별 부분 환불·쿠폰 복원을 멱등 처리한다.
  • 기존 PK·물리명·주문번호·금액·Cart 출처·15분 기한과 policy_version=0 활성 구매를 보존한다. 가격·재고 원본은 SKU로 통일한다.
  • 코드·실제 DTO/API 계약·MD/HTML·마이그레이션·회귀가 일치하고 실행 결과를 기록한 뒤 독립 Order PR 한 개를 작성한다. dev 병합·배포는 범위 밖이다.

사용자 확정과 기술 연결안

U1/U2/U3는 사용자 직접 합의다. 다만 미확정 환불1건·일반 환불off의 보상 예외는 직접 합의로 확인하지 못한 구현 선택이다. 현재 동작·영향·대안을 숨기지 않으며 정책 전체 승인으로 표시하지 않는다. 변경 검토는 별도 후속 #345/#346에 연결해 사용자 요청으로 보류하며, 현재1건 환불 제한과 일반 환불off 보상 예외는 유지한다.

외부 서비스가 같은 환불 알고리즘을 사용한다는 근거는 없다. 공식 정책 조사 기록은 대안 검토로 보존하며 사용자 결정을 바꾸지 않는다.

잠금은 신규 생성에서 회원 가드 → Cart 출처 → Product 전체 ID순 공유 잠금 → SKU 전체 ID순 쓰기 잠금이다. 완료/해제는 주문 상태를 직렬화하고 SKU ID순으로 수량을 처리한다. 환불은 주문/환불 기록 잠금 → 성공 수량·금액 → SKU 복구 → 마지막 전량 쿠폰 복원을 같은 트랜잭션에 적용한다. 외부 HTTP는 잠금 트랜잭션 커밋 뒤 호출한다.

구 productId API는 상품의 SKU가 하나일 때 지원한다. 0개는404, 여러 개는409로 새 주문서 경로를 안내한다. Sales 이력이 없는 신규 SKU도 지원하며 새 구 API 주문은 SKU 참조와 상품 스냅샷을 기록한다. 과거 Sales 참조/FK는 그대로 유지한다. 가격·재고는 SKU에서만 읽는다. Cart 옵션 SKU가 기본 SKU와 다르면 409로 새 주문서 경로를 안내하며 임의 기본 SKU로 주문하지 않는다. 이미 생성된 버전0 주문의 완료/해제/환불에는 현재 판매허용을 요구하지 않는다.

계약·실패 복구

Payment 종료/보상 계약을 구현했다. 종료 의도는 만료/선점 해제와 같은 Core 트랜잭션에 저장한다. Payment는 paymentId+원 paymentRequestId의 영속 제어키로 생성·종료·호출 시작을 직렬화한다. 이미 호출된 UNKNOWN은 실패로 단정하거나 새 승인 호출로 바꾸지 않는다. 늦은 SUCCESS 보상은 일반 환불 flag가 off여도 검증된 종료 보상만 실행·복구한다. 보상 결과는 SKU·Cart·쿠폰 효과를 재적용하지 않는다.

실제 HTTP 검사에서 서비스 인증 경로 누락403과 기본 RestClient의 숫자 Instant 직렬화400을 발견했다. 정확한 SERVICE_commercecore matcher를 추가하고 Core DTO의 Instant에 STRING 직렬화를 지정했다. 수신 Instant/ISO 검증은 유지한다. 일반 사용자 Bearer만으로 이 API를 허용하지 않는다.

의존 PR과 저장 상태

순서는 Product #333 → SKU #334 → Cart #332 → Order #331이다. PR base도 dev → Product 브랜치 → SKU 브랜치 → Cart 브랜치 순서다. 검증된 정확 SHA를 일반 merge하여 ancestry를 보존하고 cherry-pick/rebase/force push는 하지 않는다. 공통 문서 각 모듈 기록을 보존한다.

최종 통합은 ddf4d083(Order 0f59e17c + Cart 6f9dda99)이며 Product/SKU/Cart ancestry를 보존했다. 전체 통합 검증은 a68c31da, 모든 신규 주문10분 후속을 포함한 코드 HEAD는 84082563이다. 기존 구현 완료와 별도 후속 보류를 구분한다.

별도 후속과 범위 한계

#345 동시 환불·#346 결제 준비/실행 기한 분리는 사용자 요청으로 나중에 전용 작업 공간에서 진행한다. 현재 주문별 미확정 환불1건 제한·일반 환불off의 검증된 보상 예외는 그대로이며, off 중 PROCESSING 접수가 추가 환불을 막을 수 있고 기전달 요청은 flag로 취소되지 않는 경계도 유지한다. 후속의 새 환불/상태 모델이나 기한 기본값을 현재 구현 또는 확정 정책으로 채택하지 않는다.

옵션 JSON 공급·공개 다중SKU/대표가·가격순은 보류 범위다. 실제 PG 제공자·Redis·AWS·운영 배포·별도 배포된 Catalog 소비자/DB 종단은 미검증이며 dev 병합·배포는 하지 않았다. PR은 Draft를 유지하고 기존 범위 완료와 정책 전체 승인·운영 검증을 구분한다.
