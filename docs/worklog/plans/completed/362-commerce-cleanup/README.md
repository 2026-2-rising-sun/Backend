# CommerceCore 코드 가독성과 재고 처리 순서 정리

상태: 구현·로컬 검증 완료. [이슈 #362](https://github.com/2026-2-rising-sun/Backend/issues/362).

## 범위

Cart 응답의 깊은 중첩과 Order 주문서 생성 흐름을 정리한다. 기존 결제 결과가 주문 항목 ID가 아닌 SKU ID 순서로 재고를 변경하게 하고 빈 반복문·오래된 이름·미사용 의존성을 제거한다. 트랜잭션과 잠금 순서, 멱등성, 기한, 쿠폰 및 이벤트 원자성을 유지한다. Payment 구현과 보류된 환불·다중 SKU 정책은 바꾸지 않는다.

## 수용 기준

- [x] 최신 dev에서 별도 Orca 워크스페이스와 이슈 브랜치를 생성한다.
- [x] Cart 응답 구성과 주문서 생성 단계를 의미 단위로 분리한다.
- [x] 실제 재고 변경의 SKU 정렬을 보장하고 빈 반복문을 제거한다.
- [x] 변경 전 성공·실패 결과의 역순 처리 회귀 2건이 실패하는 것을 확인한다.
- [x] 변경 후 단위·통합·PostgreSQL 검사와 정적 리뷰를 완료한다.
- [x] PR 제목·본문을 게시하고 실제 저장본에서 변경 범위·검증·미실행 경계를 재검토한다.

## 기록

실행 환경과 실패·성공 결과는 [워크로그](../../../2026-11-17-commerce-cleanup.md)에 남긴다. 최종 원격 CI·dev 병합은 [PR #363](https://github.com/2026-2-rising-sun/Backend/pull/363)의 해당 head 검사·merge 기록으로 확인한다. 구현 결과와 Git 전달 상태를 구분한다.

## 결과와 후속 과제

Core 단위 176건·일반 통합 312건·PostgreSQL 업무 196건은 실패·오류·스킵 없이 통과했다. 기존 순서의 실패 2건도 보존했다. 계약·DB·Payment 소유 구현은 바꾸지 않았다. 보류된 일반/동시 수량환불과 공개 다중 SKU 정책은 이 계획의 완료 범위에 포함하지 않는다.
