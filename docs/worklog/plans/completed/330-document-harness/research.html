로컬 HEAD와 origin/dev는 e5a1b66bf3b06a971b1242dd02bd623e717c2902다. 기존 harness/의 삭제와 docs/·scripts/의 추가를 포함한 미커밋 변경이 있으며, 원본 프로젝트에서는 작업하지 않는다.

확인한 문제와 계획에 미치는 영향

확인 사항 근거 계획에 반영할 내용
루트 지침이 삭제된 경로를 가리킨다. AGENTS.md에 harness/README.md, harness/quality/, harness/workflow/ 링크가 남아 있다. 진입점과 실제 사용하는 링크를 먼저 복구한다.
기존 작업 절차가 새 기록 방향을 충분히 설명하지 못한다. workflow.md의 시작 부분은 별도 계획서·보고서가 매번 필요하지 않다는 안내만 제공한다. 기록 종류별 작성 조건과 작업 종료·인계 시점의 갱신 절차를 추가한다.
요구사항 완료가 테스트 파일 이름에 의존한다. check_docs.py의 check_requirement는 test_, Test., .test. 이름과 워크로그 링크를 요구한다. 문서·HTML 작업에 적합한 검사·브라우저·수동 검증 근거도 표현하도록 보완한다.
문서 추적 해제가 전체 검사를 선택한다. .gitignore 변경은 classify_changes.py의 기본 full-fallback으로 분류된다. 문서 패턴만 변경한 경우를 좁게 구분하고 다른 변경의 보수적인 선택은 유지한다.
새 경로의 검사 호출이 추가돼 있다. verify.py는 문서 검사를 추가하고, ci.yml은 문서 검사와 scripts/ 테스트 탐색을 호출한다. 파일 수정 사실과 실제 회귀 검사·원격 CI 통과를 구분한다.
실행 리소스와 API 계약을 문서로 처리하지 않는 분기가 있다. 변경 선택기의 document 함수는 /src/와 contracts/api/를 먼저 제외한다. 이 경계를 회귀 검사로 유지한다.

문서 검사 기준선

계획 문서와 일일 기록을 추가하기 전에 실행했다.

.venv-api/bin/python scripts/check_docs.py
  • 종료 코드: 1
  • 검사 대상: 문서 18개
  • 오류: 19개, 모두 AGENTS.md의 로컬 링크 없음
  • 대표 경로: harness/README.md, harness/workflow/README.md, harness/quality/code.md

이 결과는 현재 문서 검사기의 출력이다. 검사기 자체의 회귀 테스트 통과나 모든 Markdown 문법 지원을 증명하지 않는다. 문서 수는 이후 계획·기록 추가에 따라 달라지므로 최종 검증 때 다시 기록한다.

이번 조사에서 실행하지 않은 항목

  • 문서 검사기·실행기·변경 선택기의 전체 회귀 테스트
  • Java 빌드·서비스 테스트·실제 PostgreSQL·Kafka 검증
  • 원격 CI 및 다른 팀원의 에이전트 작업

현재 변경의 목적은 계획 수립이며 위 구현·실행 결과를 완료한 것으로 취급하지 않는다.

모듈 문서 범위 추가 조사

사용자가 모듈별 API 명세·DB ERD·상태 전이도의 HTML 문서화까지 계획에 포함하도록 요청했다. 이전 단계에서 후속 범위로 두었던 서비스별 문서를 전체 변경 계획의 단계별 산출물로 추가했다.

6개 서비스의 API YAML과 마이그레이션 경로, 상태 관련 파일 이름을 확인했다. Payment는 db/payment-migration/을 사용한다. Catalog의 판매 상태 enum 설명과 CommerceCore의 주문 상태 enum을 일부 읽었으나, 실제 허용 전이 전체는 아직 확인하지 않았다. 상태 변경 서비스·영속 필드·테스트를 함께 읽어야 한다.

조사한 경로와 앞으로 작성할 자료는 모듈별 문서 범위에 정리했다. 이 조사는 API 렌더링, DB 스키마 적용 결과, 실제 상태 전이 실행을 확인한 결과가 아니다.
