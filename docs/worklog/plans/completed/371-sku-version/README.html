#371 SKU 일반 버전 제거

이슈 · 작업 기록

목표와 범위

수정 충돌 검증에 쓰지 않는 SKU 일반 version을 DB·모델·판매 응답에서 제거한다. Product→SKU 잠금 순서, 조건부 재고 갱신, snapshotVersion과 Outbox 원자성은 유지한다. 기존 Sales·Product·Cart·Coupon·Catalog 사본 버전은 제거하지 않는다.

단계와 리뷰

  1. 모델·SQL·fixture 변경과 V107을 검토한다. 이전 마이그레이션의 원문과 과거 단계 검증은 보존한다.
  2. 판매 응답·소비자·계약·생성 문서를 대조한다. 저장소 밖 소비자와 구 인스턴스 공존 제약을 기록한다.
  3. HTTP 회귀·전체 업무 회귀·PostgreSQL 마이그레이션/경합·Catalog 중복/역순·외부 Kafka를 실행한다. 실패를 수정하고 영향 구간을 다시 검사한다.
  4. 최종 diff와 실제 검사 결과를 검토한 뒤 허용된 푸시·PR·CI 확인·병합으로 이어간다.

수용 기준

  • [x] 일반 SKU 버전만 제거하고 과거 데이터·ID 생성·이벤트 버전을 보존한다.
  • [x] 판매 등록·가격·상태 변경 응답에 version이 없고 기존 필드는 유지된다.
  • [x] 실제 PostgreSQL에서 재고 한도·경합·예약/소진/해제/복구와 Outbox 롤백이 유지된다.
  • [x] Catalog 중복·역순 반영 방지와 외부 Kafka 전달을 확인한다.
  • [x] 계약·설계·워크로그 생성과 검사, 대표 HTML 탐색·모바일 화면을 확인한다.

배포는 범위 밖이다. 구 애플리케이션이 sku.version을 참조하므로 컬럼 삭제 시 구 인스턴스를 함께 실행하지 않는다. 저장소 밖 소비자 확인은 별도 과제다.

결과와 후속

구현·소비자 조사·문서 및 로컬 회귀 846건을 완료했다. 결과와 초기 실패 수정 근거는 작업 기록에서 확인한다. 배포본·저장소 밖 소비자 확인과 실제 배포는 이번 범위 밖 후속이다. 푸시·PR의 CI/리뷰 상태는 게시된 PR에서 최종 확인한다.
