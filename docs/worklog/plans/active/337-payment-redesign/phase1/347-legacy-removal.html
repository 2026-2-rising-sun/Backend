#347 기존 Mock 결제 코드 제거

상태: 설계 확정(2026-11-15) · #343을 기다리지 않는다. #343이 먼저 병합되면 아래 표대로 바꾼다 이슈: #347 · Phase 문서: Phase 1 결제 1차

개요

끝나면 payment-service에 기존 Mock 결제·환불 코드와 그 API가 없고, 서비스는 컨트롤러 없이 기동한다. 새 코드(#348 이후)가 이름·경로·테이블에서 옛 코드와 섞이지 않게 하는 것이 목적이다. 기존 테이블은 이 PR에서 지우지 않는다. 테이블은 #348의 V4가 지운다(마이그레이션 번호를 하나로 모으기 위해).

범위

요구사항 ID 없음(삭제 작업). 근거: ADR 0337-2 "기존 구현과 호환을 맞추지 않고 교체한다".

하지 않는 것: CommerceCore 운영 코드(src/main)는 건드리지 않고 테스트 결합만 끊는다(결제 모듈 교체는 Phase 2). DB 테이블 삭제(#348 V4), 이벤트 계약 YAML 교체(#338).

CommerceCore 테스트 정리

결정(2026-11-15, 사용자 "응, 끊고 통보"): 이 PR에서 CommerceCore 테스트와 옛 Payment의 결합을 끊는다. 통보는 PR 본문과 CommerceCore 담당자에게 한다.

이유: Core build.gradle.kts의 testImplementation(project(":services:payment-service"))로 Core 테스트가 옛 Payment 서버를 별도 컨텍스트로 띄웠다(PaymentClientTestConfiguration). 모든 Core 통합 테스트의 기반 클래스 CommerceCoreSecurityTestSupport가 이 fixture를 import한다. 그래서 옛 코드를 지우면 결제와 무관한 테스트까지 Core 테스트 소스셋 전체가 컴파일되지 않는다. Payment만 바뀐 PR에서는 CI가 Core를 빌드하지 않아 이 문제를 잡지 못한다.

바꾼 것(Core src/main은 그대로):

  • build.gradle.kts의 testImplementation(project(":services:payment-service")) 삭제
  • src/test fixture 4개 삭제: PaymentClientTestConfiguration, PaymentBoundaryReconciler, RefundBoundaryReconciler, RefundBoundaryTestDriver. CommerceCoreSecurityTestSupport는 fixture import만 뺀다
  • src/integrationTest/resources/application.yml에 commercecore.payment-client.base-url: http://127.0.0.1:1을 둔다. fixture가 없으면 Core 결제 호출이 기본값 localhost:8086으로 간다. 로컬에서 띄운 Payment에 테스트가 닿지 않게 막는다
  • src/integrationTest의 payment/**에서 옛 Payment 클래스나 fixture를 쓰는 테스트 16개 파일 삭제. 남긴 것: RefundApiDisabledTest, RefundApiRequestValidationTest, RefundSchemaPostgresTest, PaymentDatabaseTestSupport(주문 테스트가 쓴다)
  • RefundTestSupport: 처음엔 지웠으나, dev 병합으로 들어온 OrderProcessingDeadlinePostgresTest(Payment 클라이언트를 spy로 끊고 Core 기한만 검사)가 쓰므로 옛 Payment 부분(paymentServer, attempts, MockPaymentEngine, createAndPay*·submitRefund·makeRefundDue)만 뺀 채 남긴다. 그 테스트의 spy 대상은 fixture 빈 boundaryPaymentClient에서 Core 빈 paymentClient로 바꾼다
  • dev 병합으로 들어온 PostgreSQL 기반 클래스 OrderSheetPostgresSupport: refundDriver·paymentServer 주입, Payment DB 행 정리, PAYMENT_TEST_POSTGRES_URL 전제를 뺀다. CommerceCoreSecurityTestSupport의 쓰이지 않는 fixture 주입 필드도 뺀다

"복구할 회귀"로 표시한 항목은 주문 연동에서 새 Payment 계약으로 다시 만든다. 지운 파일 16개의 메서드는 모두 복구할 회귀다. "되살림"은 리뷰 뒤 결제 없이 성립하는 부분만 다시 넣은 것이다.
