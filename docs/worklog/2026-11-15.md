- 변경·판단: 신규 구 API 단건/Cart 단건·묶음의 판매자 스냅샷을 저장하고 환불은 저장 원본을 우선한다. 과거 NULL 주문은 삭제 포함 불변 seller_id만 내부 조회하며 기존 주문·완료된 환불행은 일괄 재작성하지 않는다. 공개 상품 삭제 필터·판매자 권한을 유지한다. 신규 주문서 Cart 선택만 maxItems100을 선언하고 직접 SKU 항목 상한은 바꾸지 않았다. [PR343](https://github.com/2026-2-rising-sun/Backend/pull/343)

- 미실행·한계: 외부 결제제공자/운영 검증이 아니다. 과거 상품행 자체가 없거나 원 소유자가 NULL인 데이터는 추정하지 않으며 이미 완료된 NULL 환불행은 자동 재작성하지 않는다. 기존 전체 감사1376중1실패와 이번 영향8건 통과는 별개다. Payment 재설계 ADR0337이 dev에 채택돼 종료/보상 분리 검토 중이며 새 연동/삭제는 미실행이다.
- 다음 작업: 선행 SKU→Cart 일반merge 후 최종 전체/독립Kafka/브라우저/CI를 확인한다. Payment 분리안 검토 전 겹치는 수정은 보류, #340/#345/#346·공개다중SKU/옵션·미답변 Cart판매조건/0재고판매시작/중지공개노출 정책은 그대로다.

## #332 최종 감사의 Cart 소비자 호환 보완

시작 Backend는 `refactor/#332-cart-module`의 `6f9dda99`, clean이었고 fetch/upstream ff-only 동기화 뒤 동일했다. 최종 감사 기준 Order `5048413b`와 이전 Cart 브랜치를 구분했다. 기존 dev·다른 담당 작업트리·공유 kind는 수정하지 않는다.

Frontend 원격 dev `e2748d77`에서 Orca로 전용 `cart-group-compat` 작업공간과 `fix/cart-product-group-compat` 브랜치를 만들고 본인이 작업한다. 새 에이전트는 실행하지 않았다. HTTP 어댑터가 ProductGroup을 CartItem으로 읽어 ID가 undefined·수량 누락·합계 NaN이 되는 원인을 수정하며 Cart 응답의 현재 가격/재고/구매가능 표시를 Catalog 값으로 덮지 않도록 한다. 공개 다중 SKU/대표가·옵션 UI는 추가하지 않는다.

신규 OrderSheet cartItems 최대100개의 원본 스키마는 Cart 브랜치에 없다. 코디네이터가 Order 담당에게 `maxItems:100`·생성 HTML·100/101 회귀 소유권을 넘겼다. Cart는 변경 조각/감사 근거를 전달했고 직접 SKU 목록 무상한은 유지한다. 중복 스키마·임시 도메인을 만들지 않는다.

ADR/설계/ERD/계획의 과거 Cart 통합 대기 설명은 최종 Order 통합 계획과 후속 기록으로 연결한다. 과거 33실패 기록은 당시 사실로 보존하되 현재 실패로 재사용하지 않는다. 기존 선점 주문 결제 허용·새 주문 차단은 직접 사용자 합의이고, 미답변 담기 판매조건/재고0 판매시작/공개노출은 변경하거나 확정으로 표시하지 않는다. #340/#345/#346은 보류다.
