Spec

이슈 목표 동작
#416 Payment가 UNKNOWN으로 답해도 처리 기한(600초) 전에는 PAYMENT_CONFIRMING을 유지한다. 기한 전 승인(조회·PaymentApproved)은 PAID, 기한 도달 때 보상 요청을 주문당 한 번 만든다
#417 COMPENSATION_PENDING으로 바꾸는 트랜잭션에서 재고·쿠폰 예약을 한 번 해제한다. 보상 결과는 다시 해제하지 않는다. 종료 상태는 CANCELLED
#418 승인 거절이 확정되면 PENDING_PAYMENT로 되돌리고 예약을 유지한다. 원래 만료 시각 전까지 새 결제창으로 재결제한다. 거절된 인증 결과는 재사용하지 못한다. 거절마다 PaymentFailed를 보내지 않는다. Payment CANCELED는 지금처럼 주문을 끝낸다. 202 뒤 거절도 포함한다

Plan과 결정

  • 416: approvalUnknown은 전달을 UNKNOWN으로 기록만 한다. 보상은 기한 판정(OrderSheetLifecycleService.expire)이 유일하게 만든다.

  • 417: payment_group.compensation_released_at(V118)으로 해제를 한 번만 한다. 값이 없는 배포 전 보상 대기 행은 보상 완료 때 한 번 해제한다.

  • 418: 재결제 기한은 원래 주문 만료 시각이다. 승인 전달은 시도마다 남긴다(V119: 진행·성공 시도는 주문당 하나, 같은 멱등 키는 같은 시도). 거절 때 Core 결제창(pg_order_id)과 송신 표시를 비운다. 거절 판정은 422 DECLINED와 "조회가 CREATED이고 결제창이 시도의 것과 다름" 두 가지다. 후자는 202 뒤 거절과 UNKNOWN 뒤 ABORTED·EXPIRED를 함께 덮는다.

  • 리뷰·E2E 뒤 추가: 닫힌 주문의 승인 전달은 dispatch 때 TIMEOUT(ORDER_CLOSED)으로 닫고, relayDue는 next_action_at, id 순으로 뽑는다(#416). 예약 해제는 JDBC savepoint로 감싸 논리적 실패가 보상 요청을 막지 않게 했다(#417). 끝난 시도의 늦은 거절·처리중 응답은 상태를 바꾸지 않는다(#418).
