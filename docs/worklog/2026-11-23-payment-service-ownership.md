# 2026-11-23 결제 재설계 서비스 소유 정리

## #337 재설계 로드맵을 서비스 소유 기준으로 정리

- 변경·판단: 서비스마다 독립 팀이 맡는다고 가정해 남은 이슈를 소유 서비스별로 나눴다. Payment 작업은 #401, #402로 분리했고 [실행 계획](plans/active/337-payment-redesign/README.md)을 범위·소유·순서의 기준 문서로 정했다. 처음 읽는 팀원을 위한 요약, 용어, 팀별 시작점을 넣고 Phase 2·3은 별도 Phase 문서 없이 기존 기준 문서를 쓰도록 규칙을 고쳤다. 낡은 흐름 문서에는 주의 문구만 넣고 본문 수정은 #377, #384에 둔다.
- 검증: `scripts/check-docs.sh`와 설계 문서 HTML 최신성 검사를 실행했다. #377 전에 `paymentId`를 필수로 바꾸면 Core 계약 테스트의 보상 요청과 충돌하는 것을 코드로 확인해 순서에 반영했다.
- 미실행·한계: 문서 변경이라 서비스 테스트와 E2E는 실행하지 않았다.
- 다음 작업: 실행 계획의 작업 순서대로 서비스별 이슈를 진행한다.
