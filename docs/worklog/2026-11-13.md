## #330 하네스 변경 계획

관련 작업: [실행 계획](../exec-plans/completed/330-document-harness/README.md) · [판단 기준](../exec-plans/completed/330-document-harness/decision.md) · [현황 조사](../exec-plans/completed/330-document-harness/research.md)

상태: 계획 수립 · 하네스 구현 미완료

### 작업과 판단

- 하네스를 AI 에이전트의 행동 기준과 실행 절차로 정의하고, 필요한 프로젝트 지식과 실제 작업 기록을 연결하는 방향을 정리했다.
- 참고 이미지의 문서 종류별 배치를 유지하면서 복잡한 작업은 실행 계획 아래 작업 폴더로 묶는 계획을 작성했다.
- MD는 에이전트가 참조하면서 사람도 읽을 수 있는 원본, HTML은 사람이 이해할 시각 자료로 관리한다.
- 공통 ADR·날짜별 워크로그의 원본을 유지하고 작업별 판단·조사 문서에서는 링크한다. 모든 작업에 ADR·실행 계획을 새로 요구하지 않는다.
- 기존 이관을 유지하면서 진입점 복구, 기록 절차, 공유 문서와 예시, 문서 검사, CI 연결, 최종 검증의 순서를 정리했다.

### 실행한 진단

- 브랜치 `refactor/#330-document-harness`와 기존 미커밋 변경을 확인했다. 로컬 HEAD·`origin/dev`는 `e5a1b66bf3b06a971b1242dd02bd623e717c2902`다.
- 계획 파일 추가 전 `.venv-api/bin/python scripts/check_docs.py`를 실행했다. 문서 18개 중 `AGENTS.md`의 옛 경로 링크 19개가 오류로 보고되어 종료 코드 `1`이었다.
- 이슈 #330의 목표·완료 조건과 로컬 가이드·검사기·CI 정의를 대조했다. 문서 검사기 회귀 테스트와 하네스 구현 전체의 검증은 이번 계획 수립에서 실행하지 않았다.
- 계획 작성 후 관련 문서 7개의 로컬 링크·공백 검사는 오류 0개였다. 구조 MD·HTML의 80개 항목과 주석이 일치했다.
- 전체 문서는 22개로 늘었으며 검사 결과는 여전히 종료 코드 `1`, `AGENTS.md`의 기존 링크 오류 19개였다. 새 계획 문서의 검사 통과와 전체 하네스 상태를 구분한다.
- Orca 브라우저에서 구조도의 작업 폴더·계획 연결을 확인했다. 390px 화면에서 새 작업 폴더의 설명이 가로 넘침 없이 표시되는지 확인하고 데스크톱 화면으로 복원했다.

### 남은 작업과 범위

첫 구현 단계는 `AGENTS.md`의 끊긴 링크와 읽기 경로를 복구하는 일이다. 이후 기록 작성 조건, 요구사항의 검증 근거 표현, 검사기와 CI 선택을 순서대로 연결한다.

서비스 업무 코드와 API·이벤트 계약은 변경하지 않았다. Java 빌드·외부 DB·Kafka·원격 CI·팀원별 에이전트 동작은 미확인이다. 커밋·푸시·PR·병합·배포는 진행하지 않았다.

### HTML 화면 확인

- 생성한 HTML 30개를 파일 URL로 열고 1359px·390px에서 제목·내용, 문서 전체의 가로 넘침, 원격 스크립트·스타일 의존성, 이동 시 콘솔 오류를 확인했다. 두 크기에서 페이지 가로 넘침과 외부 자산 요청이 없었다. 로컬 점검 목록은 `build/harness/browser-layout.json`에 있다.

- CommerceCore 주문 상태도에서 `PAYMENT_CONFIRMING`을 선택하면 관련 전이 3/7과 조건이 표시됐다. Member ERD는 390px에서 테이블 카드와 근거 설명을 화면으로 확인했다.

- 검증: SkuServiceTest H2/Outbox Mock 9개, Catalog 저장/리스너/백필/H2 이행 33개가 각각 실패·스킵 0으로 통과했다. 초기 JDBC 테스트의 JPA auditing 컨텍스트 오류는 명시적 slice 컨텍스트로 수정했다. SKU PK 전환으로 드러난 기존 백필 fixture의 서로 다른 상품에 같은 Sales ID 사용을 올바른 식별자로 수정했다.
- 전체 선택 검사는 최초 Catalog EmbeddedKafka fixture가 서로 다른 상품에 같은 salesId·aggregateId·키를 재사용해 실패했다. SKU별 고유 ID/키를 사용하도록 fixture를 수정한 뒤 해당 EmbeddedKafka 4개가 실패·스킵 0으로 통과했다. 최초 전체 검사 결과는 build/design-handoff/SKU-최초-전체검사.json에 보존했다. 수정 뒤 전체 검사 재확인은 진행한다.
- HTML 작성 전 개인 HTML 기준과 frontend-design 지침을 확인하고 기존 프로젝트 MD→HTML 렌더러를 사용했다. ERD/상태 MD·HTML을 같은 모듈 폴더에 만들고 현재/목표·원본/코드 링크를 표시했다. Orca 브라우저로 두 HTML의 1280×900·390×844 화면, 관계 필터 2/4, 문서 지도 이동을 확인했다. 본문 가로 넘침은 없고 좁은 화면의 도식은 내부 가로 스크롤(330px 영역/580px 내용)로 확인한다. 캡처는 build/design-handoff/sku-html-check/에 보존했다.
