검증과 한계

  • 로컬 Python 환경을 준비하고 고정 의존성을 설치했다. scripts/check.sh의 문서 링크·쌍 구성, API MD/HTML·설계/기록 HTML 최신성, 선택기 회귀, API 검사기 회귀, 문서/실행기 회귀, actionlint, API 경로·이벤트 정적 검사를 통과했다. 테스트의 예상 오류 fixture 출력은 회귀 실행의 실패가 아니며 최종 종료 상태로 확인했다.
  • 선택기 회귀 45건, 문서·생성기·실행기 회귀 51건을 확인했다. API 모듈 분류의 누락·중복, 공통 인증 참조, 수작업 HTML 보존, 이동한 요구사항 검사, MD/HTML 짝 누락을 회귀에 추가했다.
  • Orca 브라우저에서 주문·결제 흐름, Product ERD, Order API를 1440px·390px로 확인했다. 흐름·ERD 확대/전체 보기와 내부 가로 이동, API의 order-sheets 검색 7/27·전체 펼치기 7개·접기 0개, 목차 이동 시 검색 해제와 해당 API 펼침, 문서 지도를 확인했다. 페이지 가로 넘침은 없었고 API 페이지 콘솔 항목은 0개였다. 검토 캡처는 임시 경로에만 두었다.
  • HTML 작성에는 개인 작성 원칙과 frontend-design, 에이전트 지침에는 writing-for-agents 기준을 적용했다. 렌더링은 저장소 Python 생성기, 화면 검토는 Orca 브라우저를 사용했다. 개인 설정은 저장소에 복사하지 않았다.

  • 서비스 업무 코드·DB 마이그레이션·API/이벤트 계약은 변경하지 않았다. Java·실제 DB·Kafka·Redis·PG·원격 CI·운영 환경은 이번 문서 변경에서 실행하지 않았다. 현재 코드의 모든 업무 의미를 재감사한 작업은 아니다.
  • 커밋·푸시·PR·병합·배포는 하지 않았다. 최종 변경은 로컬 미커밋 상태다.
