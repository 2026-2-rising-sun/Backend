# 테스트 기준

테스트 추가·수정·이동과 결과 보고에 적용한다. 태그별 실행 명령과 환경 조건의 원본 안내는 [도구](../tooling.md)에 있다.

## 필수

- 단위 테스트는 `src/test`, 통합 테스트는 `src/integrationTest`에 둔다. 패키지는 파일 이름이 아닌 실제 검증 대상을 기준으로 main 패키지에 대응시킨다.
- `@DisplayName`은 한국어로 조건과 기대 결과를 표현한다. 메서드 이름은 의미 있는 영어 식별자로 쓴다. 클래스 설명만으로 개별 테스트의 서로 다른 기대 결과를 대신하지 않는다.
- 테스트 이동 시 상속·공통 준비 코드·package-private 접근·설정 탐색·실행 선택을 확인한다. 기존 시나리오와 검증문을 보존한다.
- 태그와 실제 환경 및 실행 여부를 구분한다. 실행 결과의 실패·스킵·0건·미실행을 확인하고, 선택되지 않은 테스트를 성공으로 보고하지 않는다.

```java
@Test
@DisplayName("같은 멱등성 키로 다시 요청하면 기존 주문을 반환한다")
void returnsExistingOrderForSameIdempotencyKey() {
    // 실제 입력과 기대 결과를 검증한다.
}
```

## 태그 부착 기준

| 태그 | 의미 | 부착 대상 |
|---|---|---|
| `postgres` | 실제 PostgreSQL 환경에서 검증 | 해당 환경에 의존하는 테스트 |
| `redis` | 실제 Redis 환경에서 검증 | 실제 Redis 연결·중계를 확인하는 테스트 |
| `migration` | 마이그레이션·기존 데이터 보존·스키마 제약 검증 | 그 동작을 검증하는 테스트 |

- 클래스 전체에 해당하면 클래스에, 일부만 해당하면 메서드에 선언한다. 상속받는 테스트와 태그가 합쳐져 선택되는 범위도 확인한다.
- H2와 PostgreSQL 검사가 섞인 클래스에 `postgres`를 일괄 부착하지 않는다.
- 일반 PostgreSQL 업무 테스트를 선택시키려고 `migration`을 붙이지 않는다. `postgres`와 `migration`이 함께 적용되어야 현재 `migrationTest`에 선택된다.
- 태그는 DB를 바꾸거나 컨테이너를 시작하지 않는다. 환경변수·프로필·실제 연결 설정을 따로 확인한다.
- 일반 단위 테스트에 `unit`, `fast`, `regression` 같은 사용하지 않는 태그를 형식적으로 추가하지 않는다. 새 태그가 필요하면 선택 방식과 환경 준비를 함께 검토한다.
- 태그 변경은 기존 CI의 선택 범위에도 영향을 줄 수 있다. 변경 전후 대상 목록과 관련 [선택 로직](../../.github/scripts/ci/classify_changes.py)을 확인한다.

## 위치와 적정성의 판단 기준

- HTTP 요청·응답, 서비스 업무 규칙, 엔티티 불변조건 중 주된 검증 대상을 기준으로 배치한다. 여러 계층을 지나는 테스트는 중심 업무를 기준으로 둔다.
- 여러 도메인 흐름·보안·마이그레이션·공통 준비 코드는 역할에 맞는 예외를 허용한다. `regression`처럼 목적만 표현하는 폴더를 기본 분류로 늘리지 않는다.
- 업무 규칙·실패 조건·경계값·동시성·멱등성을 필요한 수준에서 보호한다. 기존 검증을 우선 활용하고, 개수·커버리지 수치만을 위해 테스트를 늘리지 않는다.
- 구현 순서를 그대로 복제하는 Mock 호출 검사, 겹치는 시나리오, 실제 검증보다 큰 준비 코드를 점검한다. 필수 외부 경계 호출을 보호하는 검증까지 일괄 제거하지 않는다.
- 다른 테스트가 남긴 DB·캐시·인증 상태나 실행 순서에 의존하지 않도록 전용 환경을 사용하거나 자신이 만든 데이터를 정리한다. 커밋 후 동작을 검증하는 테스트에 `@Transactional`을 일괄 적용해 롤백으로 검증 의미를 바꾸지 않는다.
- Mock·H2·실제 PostgreSQL·실제 Redis·실제 이벤트 전달은 서로 다른 증거다. 검증한 환경과 범위만 보고한다.

## 현재 실행 제약

`postgres` 단독 테스트는 일반 `integrationTest`와 `migrationTest` 모두에서 제외된다. Commerce는 격리 PostgreSQL 환경에서 `postgresTest`로 `postgres & !migration` 테스트를 실행한다. 다른 서비스는 필요한 실행 경로가 없다면 미검증으로 보고한다. `--tests`로 클래스 이름을 지정해도 태그 제외를 우회하지 못한다.

Commerce의 외부 Kafka 테스트 두 개는 환경변수로 실행을 선택한다. Commerce의 `SalesInfoMainConfigurationKafkaTest`와 Shopping의 EmbeddedKafka 테스트는 일반 통합 검사에 포함된다. 기본 빌드 성공을 외부 Kafka 전달 검증 성공으로 확대하지 않는다. 구체적인 조건은 [도구](../tooling.md)를 따른다.
