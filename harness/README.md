# Backend 작업 하네스

이해하기 쉬운 코드와 최대한 YAGNI를 기준으로, 지침을 작업·검증 흐름에 연결한다. 진입점은 [AGENTS.md](../AGENTS.md)이며 필요한 문서만 읽는다.

## 두 축

| 축 | 원본 | 역할 |
|---|---|---|
| 작업 흐름 | [작업 절차](workflow/README.md), [API·이벤트 계약](workflow/contracts.md) | 진단·필요한 계획·변경·검증·Git·리뷰의 순서 |
| 작성·품질 | [코드](quality/code.md), [테스트](quality/tests.md), [이름과 설명](quality/writing.md) | 컨벤션·가독성·YAGNI·테스트·커밋과 PR 작성 기준 |

[도구 안내](tooling.md)는 실행 명령·환경 조건, [템플릿](templates/)은 이슈·커밋·PR 작성 시 참고한다. 템플릿 항목·순서·분량을 강제하지 않는다.

## 실행 연결

변경 후 [verify.py](verify.py)로 검사 목록과 이유를 확인하고 필요한 검사를 실행한다. 실패하면 원인을 진단·수정하고 영향받은 검사를 다시 실행한다. 포맷·테스트·계약의 자동 검사와 가독성·YAGNI의 문맥 검토를 구분한다. 명령과 결과 해석은 [검증 실행](tooling.md#로컬-검증-실행기)을 따른다.

이 실행기는 기존 CI 분류와 검사 도구를 사용한다. 에이전트 시작·종료 훅, 자동 코드 수정·커밋·PR·외부 게시 기능은 없다. 실제 호출은 작업 절차로 연결하며 자동 강제라고 설명하지 않는다.

## 적용 기준

- `필수`는 지켜야 할 기준, `판단 기준`은 맥락에 따른 선택이다. 사용자의 작업 범위와 예외를 우선한다.
- 같은 규칙의 원본은 한 곳에 둔다. 도구 설정값은 실제 설정이 원본이다.
- 현재 변경에 필요한 부분만 적용한다. 작은 작업에 계획서·전체 검사·독립 리뷰·공유 기록을 일괄 요구하지 않는다.
- 범용 프레임워크는 만들지 않는다. 반복 문제가 확인되면 필요한 범위만 개선한다.
